# Product Management System — LavaLust API

Backend for **Laboratory Exercise No. 6** (CRUD with Authentication using React/Vue.js and the LavaLust API)
and the **Database Migration** laboratory activity.

- **Framework:** LavaLust v4 (PHP)
- **Auth:** JWT access token + refresh token (LavaLust `Api` library)
- **Database:** MySQL (Aiven MySQL)
- **Deployment:** Render (Docker)

---

## 1. API endpoints

All responses are JSON and are produced with the LavaLust **API library** (`$this->api->respond()`).
Everything under `/api/products` needs the header `Authorization: Bearer <access_token>`.

| Method | URL | Auth | Description |
|---|---|---|---|
| POST | `/api/auth/register` | – | Create account `{username, email, password}` |
| POST | `/api/auth/login` | – | Login `{email, password}` → `user` + `tokens` |
| POST | `/api/auth/refresh` | – | `{refresh_token}` → new tokens |
| POST | `/api/auth/logout` | ✔ | Revoke refresh token(s) |
| GET | `/api/auth/me` | ✔ | Current user |
| GET | `/api/products` | ✔ | List products (`?search=name`) |
| GET | `/api/products/{id}` | ✔ | One product |
| POST | `/api/products` | ✔ | Add product |
| PUT / PATCH | `/api/products/{id}` | ✔ | Update product (PATCH = partial) |
| DELETE | `/api/products/{id}` | ✔ | Delete product |

Product body:

```json
{ "product_name": "Wireless Mouse", "description": "2.4GHz", "price": 499.00, "quantity": 25 }
```

Without a valid token the API answers `401 {"error":"Unauthorized"}`.
Test with <https://api-tester.marasigan.dev/> or curl:

```bash
curl -X POST http://localhost:3000/api/auth/login -H "Content-Type: application/json" \
     -d '{"email":"admin@example.com","password":"Admin@12345"}'
curl http://localhost:3000/api/products -H "Authorization: Bearer <access_token>"
```

## 2. Run locally

Requirements: PHP 8.1+ with `pdo_mysql`, and a MySQL database (local or Aiven).

```bash
cp .env.example .env          # fill in DB_* values
php lava jwt:generate         # writes JWT_SECRET and REFRESH_TOKEN_KEY into .env
php lava migration run        # creates migrations, users, refresh_tokens, products
php lava serve                # http://127.0.0.1:3000
```

### Laboratory: migration commands

`CLI → Controller → Route → Migration Library → Database`

```bash
php lava migration status                              # APPLIED / PENDING
php lava migration create-migration create_xxx_table   # new file in app/migrations
php lava migration run                                 # run pending migrations
php lava migration rollback                            # undo the latest migration
php lava migration rollback-all                        # undo everything   (dev DB only!)
php lava migration refresh                             # rollback-all + run (dev DB only!)
```

The same operations are available as browser routes while `php lava serve` is running:
`/migrate`, `/status`, `/rollback`, `/rollback-all`, `/refresh`, `/create-migration/{name}`.

> They only work when `MIGRATION_ENABLED=true`. **Keep it `false` on the public server.**

Where things are:

| File | Purpose |
|---|---|
| `app/controllers/MigrationController.php` | Controller exposing the Migration library |
| `app/commands/Migration.php` | Custom CLI command `php lava migration …` (generated by `make:command` into `app/commands/`) |
| `app/migrations/000…003_*.php` | migrations, users, refresh_tokens, **products** |
| `app/controllers/AuthController.php` | register / login / refresh / logout / me |
| `app/controllers/ProductController.php` | products CRUD (JWT protected) |
| `app/config/routes.php` | migration + API routes |
| `database/schema.sql` | plain SQL version of the same schema |

## 3. Database (Aiven MySQL)

1. Aiven console → create a **MySQL** service (the free plan is enough).
2. Open the service → **Connection information**: copy *Host, Port, User, Password, Database name*,
   and download/copy the **CA certificate**.
3. Create the tables **either**:
   - run `php lava migration run` locally with the Aiven values in `.env`, **or**
   - open `database/schema.sql` in DBeaver / MySQL Workbench / the Aiven query tool and execute it.
4. Aiven requires TLS, so keep `DB_SSL=true`. Locally you can point `DB_SSL_CA=./ca.pem` to the downloaded certificate;
   on Render paste the certificate text into `DB_SSL_CA_CERT`.

## 4. Deploy the API to Render

1. Push this folder to its own GitHub repository (`.env` is git-ignored — never commit it).
2. Render → **New + → Web Service** → select the repo → **Runtime: Docker** (uses the included `Dockerfile`).
3. Add these **Environment Variables** (Render dashboard → Environment):

| Key | Value |
|---|---|
| `APP_ENV` | `production` |
| `DB_DRIVER` | `mysql` |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | from Aiven |
| `DB_CHARSET` | `utf8mb4` |
| `DB_SSL` | `true` |
| `DB_SSL_CA_CERT` | content of Aiven's CA certificate |
| `JWT_SECRET` | 64 random hex characters (`php lava jwt:generate --show`) |
| `REFRESH_TOKEN_KEY` | a **different** 64-char value |
| `ALLOW_ORIGIN` | comma-separated exact origins, e.g. `https://my-products.onrender.com,https://api-tester.marasigan.dev` |
| `MIGRATION_ENABLED` | `false` |

4. Deploy. Your **Render API URL** is `https://<service>.onrender.com` — test `GET /api/products` (should be `401`).
5. Use that URL as `VITE_API_URL` in the frontend project.

> Free Render services sleep after inactivity; the first request can take ~30–60 s.

Use the exact frontend origin with no trailing slash. Include `https://api-tester.marasigan.dev` only if you want to call the API from that browser-based tester; remove it when you no longer need it.

## 5. Security notes

- No credentials in the repository: everything comes from environment variables.
- Passwords are stored with `password_hash()` (bcrypt); refresh tokens are stored as HMAC hashes.
- Every product route calls `require_jwt()`; the frontend never connects to the database.
- Login / register / refresh are rate limited.
